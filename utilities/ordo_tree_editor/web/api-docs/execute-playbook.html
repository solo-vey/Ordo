Execute Playbook API Guide

Як зовнішній агент може завантажити playbook + Auto Answers, виконувати його в режимі Execute Playbook і автоматично забирати state/debug.

REST ReferenceOpenAPI YAML
Local integration API. За замовчуванням Editor слухає 127.0.0.1. Цей API призначений для локальної автоматизації/агентів і використовує той самий runtime boundary, що й веб-режим Execute Playbook.

Що можна автоматизувати

Агент може: завантажити playbook; завантажити replay/Auto Answers; налаштувати model provider; створити server-managed run; виконувати по одному кроку або автоматично до наступної зупинки; читати canonical runtime state та transcript; передати analyst input; зупинити run; отримати artifacts; у разі помилки одразу забрати повний debug snapshot.

Рекомендований сценарій

1. Завантажити playbook
POST /api/playbook-package
Передайте ZIP у data_base64. У відповіді збережіть package.id.
2. Завантажити Auto Answers
POST /api/replay-package
Replay package реєструється на сервері. У відповіді використайте replay_id як auto_answers_replay_id.
3. Налаштувати модель
POST /api/live-config
Виберіть provider/model і використовуйте той самий session_id у Execute run.
4. Створити run
POST /api/execute-run-start
Передайте package_id, session_id, опційно auto_answers_replay_id. Можна одразу задати advance:true.
5A. Контрольований режим
POST /api/execute-run-step
Один HTTP виклик = одна runtime phase (enter або respond). Це найкращий режим для агента, який хоче аналізувати кожен крок.
5B. Автоматичний режим
POST /api/execute-run-advance
Editor сам проходить deterministic/model steps та використовує Auto Answers до terminal/halt/error або до вузла, де бракує analyst input.
6. Якщо потрібна ручна відповідь
POST /api/execute-run-input
Передайте analyst_input; за замовчуванням після цього execution продовжиться автоматично.
7. Контролювати стан
GET /api/execute-run-status?run_id=...
Повертає current_id, canonical state, state_revision, path, transcript, outcome/error, artifact registry та посилання на debug.
8. При помилці — забрати все evidence
GET /api/execute-run-debug?run_id=...
Повертає state, history, transcript, повний debug trace, traceback помилки, artifact registry та cursors Auto Answers.

Мінімальний приклад

# 1) upload playbook
POST /api/playbook-package
{"filename":"PLAYBOOK.zip","data_base64":"..."}
# -> package.id = "abc123..."

# 2) upload Auto Answers
POST /api/replay-package
{"filename":"AUTO_ANSWERS.zip","data_base64":"..."}
# -> replay_id = "def456..."

# 3) create + auto advance
POST /api/execute-run-start
{
  "package_id":"abc123...",
  "session_id":"agent-session-1",
  "auto_answers_replay_id":"def456...",
  "advance":true,
  "max_steps":120
}
# -> run.run_id

# 4) inspect at any time
GET /api/execute-run-status?run_id=execute-...

# 5) if outcome.status == "error" or "halted"
GET /api/execute-run-debug?run_id=execute-...

Як агенту поводитися з помилкою

Рекомендований цикл: якщо outcome.status дорівнює error або halted, не реконструювати проблему з UI. Одразу викликати /api/execute-run-debug, зберегти snapshot, проаналізувати error, останній debug_trace, state, path та artifacts.

Exception під час runtime phase є fail-closed: server-managed run зберігає state до невдалого виклику й додає тип помилки, message, node, phase та traceback. Частковий state не підставляється агентом самостійно.

Низькорівневий API

POST /api/live-step залишається доступним для browser/UI та спеціальних інтеграцій. Там caller сам передає source, state, revision, history і current element. Для автономного агента рекомендовано high-level /api/execute-run-*, тому що server сам підтримує ці структури та не дозволяє зовнішньому клієнту випадково розсинхронізувати їх.

Зупинка

POST /api/execute-run-stop переводить run у halted / user_stop. Оскільки Execute REST виклики синхронні, stop застосовується між runtime phases; він не є transport-level cancellation уже активного HTTP/provider call.

Безпека. API локальний і може запускати package-local tooling playbook-а. Використовуйте його лише з довіреними playbook packages. Не публікуйте Editor server назовні без окремого authentication/security layer.
